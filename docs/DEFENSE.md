# Подготовка к защите

## Как рассказать о проекте за минуту

«Ассистент повара» хранит рецепты, ищет блюда по ингредиентам, ведёт список покупок и меню на неделю. Frontend написан на React и TypeScript и разделён по Feature-Sliced Design. Backend написан на FastAPI, разделён на маршруты, схемы, операции с данными и модели. Данные хранятся в PostgreSQL, схемой управляют миграции Alembic. Вход построен на двух токенах: короткий JWT живёт в памяти, а одноразовый refresh token лежит в HttpOnly-cookie.

## Сценарий показа

1. Откройте каталог без входа, нажмите «Показать ещё», откройте рецепт.
2. Перейдите в «Покупки»: приложение отправит на вход.
3. Покажите ошибки формы, затем войдите. Приложение вернёт на «Покупки».
4. Добавьте продукт, отметьте его, обновите страницу: данные на месте, вход сохранился.
5. Создайте рецепт, измените его, найдите через поиск, удалите.
6. Откройте чужой рецепт: кнопок изменения нет. Попробуйте открыть `/recipes/<id>/edit`.
7. Выберите блюдо в меню.
8. В профиле покажите смену пароля.
9. Сузьте окно: появится мобильное меню. Откройте несуществующий адрес: появится страница 404.
10. Выйдите. В инструментах разработчика покажите, что `localStorage` пуст, а cookie недоступна из JavaScript.
11. Покажите Swagger, пройденные тесты (`pytest`, `npm test`) и историю коммитов.

## Вопросы и ответы

### Backend и база данных

**Почему FastAPI?** Обязательный стек курса. Кроме того, он автоматически проверяет данные через Pydantic и строит документацию Swagger.

**Чем модель отличается от схемы?** Модель описывает таблицу БД, схема описывает данные API. Они разделены, чтобы, например, `hashed_password` никогда не попал в ответ.

**Что такое `Depends`?** Механизм внедрения зависимостей. FastAPI сам вызывает `get_db` и `get_current_user` перед обработчиком и передаёт результат в него.

**Зачем `yield` в `get_db`?** Код после `yield` выполняется после ответа, поэтому сессия закрывается всегда, даже при ошибке.

**Что такое миграции и зачем Alembic?** Это версии схемы БД в виде кода. `create_all` создаёт только отсутствующие таблицы и не меняет существующие, а миграции меняют схему на работающей базе без потери данных.

**Что такое проблема N+1?** Один запрос на список и ещё по запросу на связи каждой записи. `selectinload` загружает связи всей страницы отдельным запросом.

**Как устроена связь рецепта и ингредиента?** Многие-ко-многим через `recipe_ingredients`. Эта таблица хранит ещё и количество, поэтому она оформлена как отдельная модель.

**Как защищены от SQL-инъекций?** SQLAlchemy передаёт значения параметрами, а не вставляет их в текст запроса. Для `LIKE` дополнительно экранируются `%` и `_`.

**Почему PATCH, а не PUT?** PATCH меняет только переданные поля. PUT используется в меню, потому что там запрос целиком задаёт содержимое ячейки и его повтор даёт тот же результат.

**Какие статусы используются?** 200 и 201 при успехе, 204 без тела, 400 при неверном пароле в форме профиля, 401 без входа, 403 без прав, 404 нет записи, 409 конфликт, 422 ошибка валидации, 429 много попыток, 503 БД недоступна.

### Безопасность

**Почему Argon2id, а не SHA-256?** SHA-256 считается очень быстро, поэтому пароли легко перебирать. Argon2id намеренно требует времени и памяти, а соль добавляет автоматически.

**Что такое JWT?** Подписанная строка из заголовка, данных и подписи. Сервер проверяет подпись и не обращается к хранилищу. Данные в JWT не зашифрованы, поэтому там только id пользователя и служебные поля.

**Зачем два токена?** JWT нельзя отозвать, поэтому он живёт недолго. Refresh token живёт долго, но проверяется в БД и может быть отозван.

**Почему refresh token не JWT?** Его всё равно нужно хранить на сервере для отзыва, поэтому подпись ничего не даёт. Случайная строка проще.

**Что такое ротация?** При обновлении старый токен отзывается и выдаётся новый. Украденный токен работает максимум до первого обмена.

**Почему токен не в `localStorage`?** Любой скрипт на странице может прочитать `localStorage`. Cookie с HttpOnly из JavaScript недоступна.

**Как защищены от CSRF?** `SameSite=Lax` не отправляет cookie в POST с чужого сайта. Защищённые маршруты используют заголовок Authorization, который браузер сам не добавляет.

**Что происходит с токеном после выхода?** Refresh token отзывается, cookie удаляется, состояние очищается. Access token может действовать до 15 минут: это известное ограничение JWT.

**Зачем `with_for_update`?** Блокирует строку на время транзакции. Без него два параллельных запроса могли бы обменять один токен дважды.

**Почему права проверяются на сервере, если кнопки скрыты?** Запрос можно отправить напрямую, минуя интерфейс. Интерфейс не является защитой.

**Почему нет CORS?** Frontend и API находятся на одном адресе благодаря прокси.

### Frontend

**Что такое FSD?** Способ разделить код по слоям ответственности. Импорты идут только сверху вниз, поэтому изменения меньше расходятся по проекту.

**Почему `features` отделены от `entities`?** Сущность описывает, что это такое (рецепт). Фича описывает, что делает пользователь (удаляет рецепт).

**Зачем `AuthProvider`?** Данные пользователя нужны многим компонентам. Контекст даёт к ним доступ без передачи через все уровни.

**Что будет при обновлении страницы?** Access token в памяти пропадает. `AuthProvider` вызывает `/auth/refresh`, браузер сам отправляет cookie, сессия восстанавливается.

**Зачем общий `refreshPromise`?** Токен одноразовый. Если несколько запросов обновят его одновременно, все кроме первого получат 401 и пользователя выкинет.

**Как устроено оформление?** Используется MUI. Палитра, шрифты и вид компонентов заданы в `app/theme.ts`, поэтому интерфейс единый и меняется в одном месте. Шрифты лежат в проекте, внешних запросов нет.

**Почему поиск хранится в адресе?** Результат не пропадает при обновлении страницы, им можно поделиться, а кнопка «Назад» работает ожидаемо.

**Что такое `lazy` и `Suspense`?** `lazy` загружает код страницы при первом переходе, `Suspense` показывает индикатор на это время. Первая загрузка становится легче.

**Как работает адаптивность?** Сетка `Grid` и значения `sx` для разных ширин экрана. Ниже ширины `md` ссылки шапки заменяются меню `Drawer`.

**Как обновляется интерфейс после изменения данных?** Состояние обновляется ответом сервера или после перехода страница заново загружает данные.

### Качество и запуск

**Какие тесты есть?** Backend проверяет API на настоящем PostgreSQL. Frontend проверяет API-клиент и валидацию.

**Почему тесты используют настоящий PostgreSQL?** В коде есть особенности PostgreSQL: `FOR UPDATE`, `ON CONFLICT`, `ILIKE`. SQLite повёл бы себя иначе.

**Зачем Docker?** Приложение запускается одинаково на любом компьютере одной командой, вместе с нужными версиями PostgreSQL и nginx.

**Зачем nginx, если есть Vite?** Vite предназначен для разработки. nginx быстро отдаёт готовые файлы, сжимает их, управляет кэшем и добавляет заголовки безопасности.

**Что такое CI?** Автоматический запуск проверок при каждом push, чтобы ошибка не попала в основную ветку незамеченной.

**Что вы бы улучшили дальше?** Восстановление пароля по email, загрузку изображений, поиск по названию, счётчики лимита входа в Redis. Подробнее в `ARCHITECTURE.md`.
