# Чек-лист запуска

Код готов к развёртыванию. Пункты ниже нельзя закрыть в репозитории: они зависят от вашего сервера, договоров и решений.

## Обязательно перед запуском

### Сервер и данные

- [ ] Арендовать сервер и домен.
- [ ] Настроить HTTPS. Без него браузер не отправит cookie с `REFRESH_COOKIE_SECURE=true`.
- [ ] Добавить заголовок `Strict-Transport-Security` на узле, где настроен HTTPS.
- [ ] Создать новые значения `POSTGRES_PASSWORD` и `JWT_SECRET_KEY`. Значения из разработки использовать нельзя.
- [ ] Настроить ежедневное резервное копирование БД и тома `uploads` с фото, проверить восстановление из копии.
- [ ] Закрыть на сервере все порты, кроме 80 и 443.
- [ ] Подключить мониторинг адреса `/api/health` и сбор логов.
- [ ] Не запускать `app.seed` на настоящем сервере, если демо-пользователь там не нужен.

### Юридические вопросы

Эти пункты нужно согласовать с юристом. Приложение хранит email, значит обрабатывает персональные данные.

- [ ] Подготовить политику обработки персональных данных и пользовательское соглашение.
- [ ] Добавить ссылки на них и согласие при регистрации.
- [ ] Проверить требования 152-ФЗ, включая уведомление Роскомнадзора и хранение данных граждан РФ на серверах в России.
- [ ] Заменить демонстрационные рецепты и изображения. Картинки загружаются по внешним ссылкам, прав на них у проекта нет.

### Деньги

Оплаты в приложении нет. Для продажи нужно выбрать модель (подписка, разовая покупка), заключить договор с платёжным сервисом, реализовать оплату и чеки. Данные карт нельзя хранить в своей БД.

## Желательно в ближайших версиях

- [ ] Восстановление пароля и подтверждение email. Нужен почтовый сервис: сейчас забытый пароль восстановить нельзя.
- [ ] Перенос фото в объектное хранилище, если приложение будет работать на нескольких серверах.
- [ ] Поиск по названию рецепта и в диалоге выбора блюда.
- [ ] Роль администратора для модерации рецептов и справочника ингредиентов.
- [ ] Счётчики лимита входа в Redis, если backend будет работать в нескольких процессах.
- [ ] Лимит на регистрацию и создание рецептов.
- [ ] Сбор ошибок frontend, например Sentry.

## Проверка перед каждым выпуском

- [ ] Проверки в GitHub Actions пройдены.
- [ ] Сделана резервная копия БД.
- [ ] `docker compose up -d --build` выполнен, миграции применились без ошибок.
- [ ] `/api/health` отвечает `{"status":"ok"}`.
- [ ] Вход, создание рецепта и выход работают на настоящем сервере.
