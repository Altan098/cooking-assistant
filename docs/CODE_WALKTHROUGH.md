# Разбор кода

Сначала показан путь реальных запросов, затем описан каждый файл. Читать удобнее с открытым кодом.

## Путь запросов

### Вход пользователя

1. `features/auth/LoginForm.tsx` описывает поля и вызывает `login` из контекста.
2. `features/auth/useAuthForm.ts` проверяет поля функцией `validateLogin`. При ошибке запрос не отправляется.
3. `features/auth/AuthProvider.tsx` вызывает `loginRequest`.
4. `shared/api/client.ts` отправляет `POST /api/auth/login`.
5. Сервер Vite или nginx передаёт запрос в FastAPI.
6. Схема `UserLogin` проверяет JSON и приводит email к нижнему регистру.
7. `routers/auth.py: login` проверяет лимит попыток, ищет пользователя и проверяет пароль.
8. `start_session` сохраняет хеш refresh token, ставит cookie и возвращает access token.
9. `AuthProvider.startSession` кладёт токен в память и записывает пользователя в состояние.
10. `LoginPage` видит статус `authenticated` и перенаправляет на исходную страницу.

### Автоматическое обновление токена

1. Функция `api` в `client.ts` получает 401 на обычный запрос.
2. Она вызывает `refreshSession`. Параллельные запросы получают один и тот же промис, поэтому на сервер уходит один запрос.
3. Если обновление удалось, исходный запрос отправляется ещё раз.
4. Если сервер вернул 401, вызывается `sessionExpiredHandler`. `AuthProvider` очищает состояние, а `RequireAuth` ведёт на `/login`.
5. Сбой сети сессию не завершает: пользователь увидит ошибку и сможет повторить.

### Создание рецепта

1. `useRecipeForm` проверяет значения и превращает их в `RecipeInput`.
2. `NewRecipePage` вызывает `createRecipe` из `entities/recipe/api.ts`.
3. `toDto` переводит поля в формат API.
4. `get_current_user` проверяет JWT и находит пользователя.
5. Схема `RecipeCreate` проверяет длину полей и убирает лишние пробелы.
6. `crud/recipe.py: create_recipe` находит или создаёт ингредиенты и сохраняет всё в одной транзакции.
7. Автор берётся из токена, а не из запроса, поэтому нельзя создать рецепт от чужого имени.
8. `NewRecipePage` отправляет выбранный файл через `uploadRecipeImage`. Файл идёт в `FormData`, поэтому `client.ts` не ставит заголовок JSON.
9. `upload_recipe_image` проверяет автора и размер, `save_image` кодирует файл заново.
10. Страница переходит на созданный рецепт. Если фото не загрузилось, рецепт уже существует, поэтому открывается его редактирование с предупреждением.

### Изменение чужого рецепта

`PATCH /api/recipes/5` вызывает `get_own_recipe`. Функция сравнивает `recipe.author_id` с `current_user.id` и возвращает 403. `client.ts` превращает ответ в `ApiError`, а форма показывает текст ошибки.

## Backend

### Точка входа

| Файл | Назначение |
| --- | --- |
| `app/main.py` | Создаёт приложение, настраивает логи, подключает маршруты с префиксом `/api`. В production отключает документацию |
| `app/dependencies.py` | `get_current_user`: достаёт Bearer-токен, проверяет его и находит пользователя. На любой сбой отвечает 401 |
| `app/seed.py` | Создаёт демо-пользователя и рецепты из `seed_recipes.json`. Уже добавленные рецепты пропускает |

### `app/core` — инфраструктура

| Файл | Назначение |
| --- | --- |
| `config.py` | Класс `Settings` читает настройки из `.env` и окружения и проверяет их при старте. Без `DATABASE_URL` или с коротким секретом приложение не запустится |
| `database.py` | Создаёт `engine` и фабрику сессий. `get_db` выдаёт сессию на один запрос и закрывает её в `finally` |
| `security.py` | Хеширование паролей, создание и проверка JWT, генерация refresh token |
| `rate_limit.py` | Класс `AttemptLimiter`: счётчик неудачных попыток входа |
| `images.py` | Проверка, обработка, сохранение и удаление фото |
| `logging.py` | Единый формат логов |

**`security.py`.** `verify_password` перехватывает ошибки библиотеки и возвращает `False`, поэтому старая запись с паролем открытым текстом не приведёт к ошибке 500. `DUMMY_PASSWORD_HASH` нужен для выравнивания времени: если email не найден, всё равно проверяется хеш.

`decode_access_token` явно задаёт `algorithms=[...]`, поэтому поддельный токен с `alg=none` не пройдёт, и проверяет поле `type`.

Refresh token хешируется быстрым SHA-256, а пароль медленным Argon2id. Причина: пароли придумывают люди, их можно подбирать по словарю, поэтому хеш должен считаться долго. Токен содержит 48 случайных байт, подобрать его нельзя.

**`rate_limit.py`.** Скользящее окно: хранится время каждой неудачи, старые значения отбрасываются. `Lock` нужен потому, что FastAPI выполняет обычные функции в нескольких потоках. Ключ состоит из IP и email. Если бы ключом был только email, злоумышленник мог бы намеренно заблокировать вход чужому пользователю. С IP в ключе блокируется только атакующий адрес, а настоящий владелец войдёт со своего.

| Файл | Таблица | Особенности |

| Файл | Ключевые функции |

| `recipe.py` | `filtered_recipes` собирает условия один раз для списка и подсчёта. `escape_like` экранирует `%` и `_`, чтобы поиск воспринимал их как текст |

| Файл | Маршруты |
| --- | --- |
| `auth.py` | Регистрация, вход, обновление, выход, смена пароля |

### `shared`

**`api/client.ts`** — центральный файл обмена с сервером.

- `accessToken` — обычная переменная модуля. Не попадает в `localStorage`, исчезает при перезагрузке и восстанавливается по cookie.
- `send` собирает запрос и превращает сбой сети в `ApiError` со статусом 0.
- `toApiError` переводит ответ сервера в понятный текст.
- `refreshSession` хранит текущий запрос в `refreshPromise`. Это обязательно: токен одноразовый, а `StrictMode` и параллельные запросы вызвали бы обновление несколько раз.
- `api` — функция, через которую идут все запросы. Маршруты `/auth/*` не обновляют токен: 401 при входе означает неверный пароль.

**`lib/useRequest.ts`** загружает данные при изменении зависимостей. Счётчик `lastRequest` защищает от гонки: если пользователь быстро сменил поиск, ответ на старый запрос будет проигнорирован.

`getErrorMessage` показывает текст только ошибок API. Внутренняя ошибка JavaScript заменяется общим сообщением, а подробности уходят в консоль: пользователь не должен видеть технический текст.

**`ui/DataState.tsx`** принимает состояние `useRequest` и функцию отрисовки. Свойство `loader` позволяет показать свой индикатор, например скелетоны карточек. Кнопка «Повторить» показывается только там, где повтор может помочь: при сбое сети и ошибках сервера.

### `pages`

`SearchPage` хранит запрос в адресе (`?ingredient=курица`) через `useSearchParams`: его можно обновить и отправить ссылкой, а поиск с главной просто переходит на этот адрес.

Страницы только собирают экран. `index.ts` объявляет `lazy`-импорты: код страницы загружается при первом переходе. `ErrorPage` импортируется обычным способом, потому что должна работать, даже если не загрузился другой файл.
